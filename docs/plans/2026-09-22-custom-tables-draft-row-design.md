# Строка-черновик в custom-tables

Дата: 2026-09-22

## Проблема

Кнопка «+» в гриде отправляла `POST /custom-tables/{id}/rows` с телом `{ data: {} }`.
Бэкенд в `createRow` проверял обязательные колонки без флага `partial`, поэтому в
таблице с любой колонкой `isRequired` пустая строка не создавалась никогда: летел
`COLUMN_REQUIRED_VALUE` и 400. Тост показывал generic «Failed to add row», так что
причина из UI не читалась.

## Решение

«+» больше не пишет на сервер. Строка живёт локально как черновик и уходит на
сервер одним POST, когда заполнены все обязательные колонки.

### Где живёт черновик

Отдельного стора нет. Черновик — обычная строка в существующем `rows` с
`id = 'temp-<n>'`. Ветки `startsWith('temp-')` уже написаны по всему коду (правка
ячейки, правка из дровера, стиль строки, удаление, массовое удаление) и держат
такие строки вне сети — они начинают работать сами собой.

- `createRow` добавляет `{ id: temp, rowNumber: rows.length + 1, data: {}, styles: null }`
  и возвращает её. Тоста на «+» нет — сохранять пока нечего.
- Temp-id из счётчика в `useRef`, не из `Date.now()`: два быстрых клика дали бы
  одинаковый id.

### Когда уходит POST

`promoteDraftRow` вызывается из temp-ветки `updateCellFromGrid` и
`updateRowFromDrawer` сразу после локального патча.

- Условие: все колонки с `isRequired` непустые по правилу бэкенда
  (`isBlankCellValue`: null/undefined, пустой массив, строка из пробелов).
- Обязательных колонок в таблице нет → запись по первому непустому значению.
- `POST { data: <все накопленные значения> }`, затем temp-строка заменяется на
  месте: серверные `id` и `rowNumber`, позиция в списке сохраняется,
  дёргается `refreshStats`.
- Готовность считается по всем колонкам таблицы, а не по видимым.

### Ошибки

POST упал (например, дубль в unique-колонке) — строка остаётся черновиком,
показывается ошибка, следующая правка ячейки пробует снова. Данные не теряются.
От двойной записи при быстрых правках защищает ref-множество id, которые сейчас
в полёте.

### Визуал

- `buildRowNumberColumn`: для temp-строк маркер вместо номера + подсказка.
- `renderDataCell`: temp-строка + `isRequired` + пустое значение → мягкая рамка,
  подмешанная в существующий `cellStyle`.
- `MobileTableView`: тот же маркер вместо `#{rowNumber}`.
- `isRequired` добавляется опциональным полем в базовый `CustomTableColumn`
  (грид типизирован им, а не `CustomTablePageColumn`).

## Найдено по дороге: разбор ответа на создание строки

`extractPayload` в `rowActionHelpers.ts` разворачивал конверт правилом
`d.data ?? d.item ?? data`. Эндпоинт `POST /rows` конверта не имеет (глобального
transform-интерцептора в приложении нет) и отдаёт саму сущность строки, у которой
есть собственное поле `data` со значениями ячеек. Правило забирало именно его,
`getCreatedRowResponse` не находил `id` и подставлял `temp-${Date.now()}`.

До черновиков это означало, что добавленная строка никогда не получала серверный
id: все последующие правки её ячеек уходили в temp-ветку и молча не сохранялись
до перезагрузки страницы. Для черновиков это блокирующая ошибка — промоушен
опирается на серверный id.

Исправлено: конверт разворачивается только тогда, когда снаружи лежит не строка
(нет ни `id`, ни `rowNumber`). Плюс `parseCreateRowResponse` теперь возвращает
`null`, если серверного id в ответе нет, — вместо того чтобы выдавать строку с
временным id за сохранённую.

## Известные ограничения

- Черновик нигде не персистится: перезагрузка страницы, смена фильтра,
  сортировки или вкладки его теряют. Об этом и говорит маркер.
- Если обязательная колонка скрыта в текущем виде, заполнить её в гриде негде
  и черновик останется черновиком. Спецкейса на это нет.

## Отвергнутые варианты

- **Послабление на бэкенде** (разрешить создание пустой строки, если `data`
  пустой). Сделано временно и откатывается: строка с пустой обязательной
  колонкой оставалась в базе навсегда, а дырка открывалась и для остальных
  клиентов API.
- **Явная кнопка сохранения на строке-черновике.** Предсказуемо, но ломает
  спредшит-логику: все остальные правки в гриде сохраняются сами.
- **Запись по уходу фокуса со строки.** Ближе к Excel, но «уход фокуса» в гриде
  ловится ненадёжно (дропдауны, датапикеры, скролл), и при незаполненной
  обязательной колонке всё равно нужно решать, что делать.
