# Подача UStVA через ELSTER (ERiC): как сделать

Состояние: 2026-10-11, разбор и предложение. Ничего не реализовано.

## Что проверено

Источники перечислены в конце.

- **ERiC** — C-библиотека налоговой (BayLfSt) для проверки и отправки данных в ELSTER.
  - Бесплатна (§ 2 Lizenzvertrag).
  - Платформы: Windows, Linux x86_64, macOS, AIX, Linux ppc64le. arm64 нет.
  - **Скачивается публично, без входа:** `https://download.elster.de/download/eric/eric_43/ERiC-43.4.6.0-Linux-x86_64.jar`, 472 МБ (HEAD 200, проверено 2026-10-11).
- **Лицензия (2018):**
  - разрешено встраивать ERiC в свой продукт и распространять его вместе с продуктом как одно целое (§ 4(1));
  - передавать лицензию третьим лицам и сублицензировать нельзя (§ 4(2));
  - поддержку пользователей и обновления оплачивает и обеспечивает производитель (§§ 6–7);
  - пользоваться разрешено не ниже «Mindestversion» (§ 5(6));
  - при нарушении налоговая может заблокировать Hersteller-ID (§ 8);
  - пользователю нужно показать уведомление о защите данных налоговой (§ 5(1–2)).
- **Hersteller-ID:** «Jeder Softwarehersteller braucht mindestens eine eigene Hersteller-ID … produktbezogen». Она нужна и для настоящих отправок, и для тестов. Старый тестовый ID 74931 остался только в документации как пример (Entwicklerhandbuch 43.3, гл. 6.5.3). Получить ID: зарегистрироваться как производитель на elster.de (проверка BayLfSt, несколько дней), затем подать заявку «Anträge und Formulare».
- **Тесты:** признак `Testmerker` (например, 700000004) — сервер принимает данные и сразу удаляет. С настоящими данными признак ставить нельзя (гл. 6.5.5).
- **Релизы:** два в год — основной в середине ноября и технический в начале мая. Минимальная версия поднимается раз в год, в апреле; более старые версии сервер отклоняет. Отсюда минимум два обновления в год.
- **Аутентификация:** UStVA с 2013 года подаётся только аутентифицированно. Варианты:
  1. Сертификат самого пользователя из Mein ELSTER (.pfx + PIN). Так сделано в haben.
  2. Lexware и sevdesk подают со своим сертификатом как передатчик данных по § 87d AO. Тогда передатчик обязан идентифицировать заказчика, хранить записи 5 лет и показывать данные на проверку. Это модель SaaS, а не self-hosted.
- **Прецедент — `firsttris/haben`** (AGPL, self-hosted, бухгалтерия для DE, работает с настоящим ERiC 43):
  - ERiC не входит в образ, его по кнопке скачивает оператор с download.elster.de в отдельный volume;
  - Hersteller-ID у каждого оператора свой (env `ELSTER_HERSTELLER_ID`), без него доступна только тестовая отправка;
  - сертификат лежит в базе зашифрованным, PIN не хранится;
  - каждый вызов ERiC идёт в отдельном короткоживущем дочернем процессе с таймаутом;
  - есть кнопки «только проверить», «тестовая отправка» и «отправить» с двойным подтверждением;
  - журнал попыток только дополняется; после отправки сохраняются Transfer-Ticket и PDF-протокол, а запись блокируется;
  - есть уточнённая декларация (Kz 10);
  - без ERiC работает имитация.

## Предлагаемые этапы

**E0 — без ERiC, полезно сразу.**
- Наш расчёт НДС раскладывается по клеткам (Kennzahlen) официального бланка UStVA на нужный год. По каждой клетке можно раскрыть список операций, рядом кнопки «скопировать» для ручного ввода в Mein ELSTER.
- Сопоставление с клетками нужно проверить по BMF-Schreiben «Muster des Vordrucks UStVA 2026», а не брать из памяти. Сейчас уверенно известны только клетки, которые haben генерирует для простого случая: 81, 86, 66, 83, а также 10/21/45/48.
- Пробел в данных: поставки и приобретения внутри ЕС (41, 89/93, 61) и § 13b для услуг (46/47) против прочего (84/85) требуют различать товары и услуги. Сейчас у нас есть только признак RC и страна контрагента.

**E1 — проверка и тестовая отправка.**
- ERiC скачивается в отдельный volume по кнопке после согласия с условиями, только x86_64.
- Вызов через FFI (`koffi`) в дочернем процессе.
- Генерация ElsterXML `UStVA_<год>`, кнопка «только проверить».
- Загрузка сертификата .pfx: шифруем существующим `INTEGRATIONS_ENCRYPTION_KEY`, PIN не храним.
- Тестовая отправка с признаком Testmerker.

**E2 — настоящая отправка.**
- Двойное подтверждение.
- Успешная отправка подаёт декларацию у нас (строки уже блокируются) и сохраняет Transfer-Ticket и PDF-протокол.
- Журнал попыток только дополняется.
- Уточнённая декларация (Kz 10).
- Напоминание об истечении сертификата.

**Сопровождение:**
- в ноябре — новый ERiC и `UStVA_<год>` / изменения клеток;
- в апреле — проверить, что минимальная версия не старше нашей.

Это входит в ежегодную перепроверку (пункт 4 плана по справочникам).

## Решения за Symon

1. **Чей Hersteller-ID.** ID привязан к продукту, поэтому логично, что Lumio получает один ID на Symon. Риски:
   - налоговая блокирует ID за нарушения, и один недобросовестный self-hoster может заблокировать отправку всем;
   - форк — это другой продукт.

   Предложение: как в haben, ID задаёт оператор (`ELSTER_HERSTELLER_ID`). Официальная облачная установка, если появится, использует ID Symon.
2. **Регистрация Symon как производителя.** Она нужна в любом случае: без своего ID не работают даже тестовые отправки.
3. **Только сертификат пользователя.** Модель § 87d (подаём своим сертификатом за клиентов) сознательно не делаем.

## E0 — сделано (2026-10-11, не закоммичено)

- **Источник:** письмо BMF от 29.12.2025, III C 3 - S 7344/00039/007/036: бланк USt 1 A 2026 и инструкция USt 1 E. Сайт Минфина закрыт проверкой на бота, поэтому текст взят с зеркала IHK Hannover и лежит в `docs/plans/ustva-2026-10-11/bmf-2025-12-29-ustva-2026.txt`. Бланк 2025 года (скан без текстового слоя) не поддержан.
- **`modules/tax/ustva/ustva-form.ts`** — чистая функция `buildUstva(year, rows)`.
  - Разносит строки по клеткам: 81/86/35+36 (продажи), 41/21 (продажи в ЕС, товары/услуги), 66 (входной НДС), 46/47+67 (услуги ЕС, § 13b), 89/93/95+98+61 (приобретение товаров в ЕС).
  - Базы суммируются в центах и вносятся в целых евро, центы отбрасываются. Kz 83 считается, как бланк: 19 %/7 % от целой базы плюс введённые налоги минус вычеты.
  - То, что разнести нельзя, попадает в открытые пункты:
    - 0 % — строка 15, 22 или 23, решает пользователь;
    - reverse charge у контрагента, для которого не указано «товары» или «услуги».
- **`UstvaService` + `GET /tax/returns/ustva`.** Работает только для DE и только для плательщиков НДС. Строки берутся те же, что в декларации по НДС, плюс строки 0 %. Каждая сумма пересчитывается по курсу на дату операции. Флаг `sondervorauszahlungDue` ставится для декабря при помесячной подаче с Dauerfristverlängerung.
- **`payees.supply_type`** (миграция `1787150000000`, нужен db-approved — это шестая такая миграция):
  - выбирается в форме VAT контрагента;
  - и кнопками прямо в открытом пункте.
- **UI:** `UstvaCard` на вкладке «Tax return».
  - Строка бланка, Kz, официальная немецкая подпись, сумма в формате ELSTER («1251» / «57,01»).
  - Кнопка «Copy», список операций по клетке, Kz 83, открытые пункты.
  - Подпись об основе расчёта и ссылка на бланк.
  - Тексты на 35 языках.
- **Проверено:**
  - unit 8;
  - e2e 4;
  - vitest 38;
  - вживую на dev: Kz 66 = 190, после «Services» — Kz 46/47/67, Kz 83 = −190, совпадает с нашей декларацией по НДС; 390 px без горизонтального скролла.
- **Не сделано:**
  - Ist/Soll: цифры считаются по датам операций;
  - Kz 39 (сумма Sondervorauszahlung неизвестна, показывается только подсказка);
  - Kz 10 (уточнённая декларация);
  - ZM (Zusammenfassende Meldung) для строк 19/35.
