# Security audit — 2026-10-20

Scope: every backend module (67 under `backend/src/modules`) plus the platform layer (guards, interceptors, egress, uploads, deployment, frontend boundary). Commit audited: `origin/main` 43af3ca7. Method: code reading route → service → query for every module; nothing was executed against a live instance. Per-group reports with full exploit traces and evidence live in [`audit-2026-10-20/`](audit-2026-10-20/).

Prior isolation work (PR #188/#197, #291/#292 sweep) holds: no route serves another workspace's rows by id, every controller carries a workspace guard, all 70 raw SQL sites are parameterised, `npm audit --omit=dev` is clean. What remains falls into four recurring patterns listed after the table.

## MEDIUM (grouped)

**Private rows (`isPrivate` / `owner_member_id`) leak outside `TransactionsService.findAll/findOneFor`.** Redaction exists only there. Merchant/purpose of other members' private rows come back from: rule test, duplicates/detect, transfer- and reimbursement-candidates, `PUT /transactions/:id` response, split parts, `/classification/transaction/:id` (group3 #2); `GET /search` (group2); receipts `transaction-matches`, statements list `transactionSummary.description` (group2); goal flow merchant nodes, subscription detection vendor, payees `lastSeen` (group3 #5); custom-tables "Fill from app" source (group4); storage statement CSV export (group4); dashboard recent/top merchants/income sources, all report exports, cash-flow-map, spend-flow, forecast party lists (group6 #2); VAT return lines, USt-VA, income-tax contributions, DATEV mapping counts (group6 #3, group5 #8).

**Write routes behind read permissions or no permission.** `/classification/*` (no PermissionsGuard: viewers reclassify and overwrite manual categories, group3 #3); balance-sheet snapshot/accounts (group3 #4), all investments and metals mutations (group7) under `REPORT_VIEW`; entity-imports and search without PermissionsGuard (API-key scopes bypassed, group2); Telegram bot actions check membership only (demoted viewer creates/deletes via bot, group8 #3); webhook subscriptions/inbound tokens creatable with the statements toggle instead of `INTEGRATION_MANAGE` (group8 #5); metals `addLot.ownerUserId` unvalidated (group7).

**Home-workspace fallback for SMTP.** `requireWorkspaceId` falls back to `users.workspace_id`: invoice reminders (`smb.service.ts:213,236`, group5 #2), workspace invitation mails (group1 #7), notification e-mails (group8, LOW) all send through the inviter's/recipient's home-workspace SMTP credentials and public URL instead of the open workspace's.

**Spreadsheet formula injection.** Payables CSV, subscriptions CSV, income-tax document, tax-return document, Gmail receipt xlsx, manual-expense/entity-import generated statements, custom-tables CSV headers: strings written without `neutralizeSpreadsheetFormulaCell` (group5 #3, group3 #6, group9 #2, group2, group4).

**Other MEDIUM.** Account-level `users.permissions` grants override the workspace role in every workspace (group9 #1, LIKELY). `trust proxy 1` with the API port published on all interfaces lets direct clients forge `X-Forwarded-For` past the login/2FA/reset throttles (group9 #3, LIKELY). `PUT /users/:id` changes own e-mail with no verification or password (group1 #5). `scopes: []` becomes an unrestricted legacy API key (group1 #6). Workspace admin sets `localModelPath` (filesystem probe, shared model dir, group1 #8). Gmail `PATCH receipts/:id` nested `parsedData` mass-assignment ignores `taxLocked` (group8 #6). Push endpoint URL POSTed without egress check (blind SSRF, group8 #4). Storage: uploader keeps full access to files in a workspace they left; `bulkDelete` hard-deletes past trash/audit/tax-lock (group4). Report schedules keep mailing ≤20 arbitrary recipients after the creator is removed (group6 #4). Backup preview: nested zip + `JSON.parse` of 200 MB in memory, no throttle (group7, LIKELY).

## Suggested fix order

1. **C1/H1/H2 backups restore**: allow-list restorable tables (only ones with `workspace_id`), drop any `*Id` that is not in the id map (or null it), add `token` and `password` to the nulled properties, cap decompressed size.
2. **C2 telegram**: persist the bot id on the user at link time and require `botIdOf(botToken) === user.telegramBotId` in `findUserByTelegram`; check role/permissions per bot action.
3. **C3 reports**: write under `uploads/reports/<workspaceId>/<uuid>-<base>.<ext>` and assert containment on download; same for payables export and gmail xlsx export.
4. **H3–H8 body ids**: one helper (`assertWorkspaceOwnedRefs` already exists in transactions) called from rule create/update, receipts update/bulk-approve, gmail approve paths, convert-dropped-sample, invoice line items; scope `walletOwnerMemberId` by workspace; tighten `parsedData` contracts.
5. **H9 custom-tables**: name the file `${schedule.id}-${date}.${ext}` and assert `path.resolve` stays under the directory.
6. **H10–H13 workspaces/api-keys**: refuse `owner` in invitations, accept only `PENDING` invitations and cancel them on member removal, stop returning invitation tokens from `/workspaces/me`, run `assertPermissions` (scopes) on JwtAuthGuard-only routes or make `PermissionsGuard` global with a deny-by-default for API keys.
7. **Private rows**: a single `redactPrivateRows` pass in every listed response and a `canReadPrivate` filter in aggregate SQL; add `transaction-privacy.e2e-spec` cases for each route.
8. **Permissions**: `TRANSACTION_EDIT` on `/classification/*`, a write permission for balance/investments/metals, `INTEGRATION_MANAGE` for webhooks, PermissionsGuard on entity-imports/search.
9. **Formula injection**: route every export through `neutralizeSpreadsheetFormulaCell`.
10. **SMTP workspace**: pass the open `workspaceId` to `MailerService.send/isConfigured` from reminders, invitations and notifications.
